# 中文召回对照

用固定的合成语料比较现状、FTS5 混合召回以及混合召回加本地语义候选。22 个问题包括 4 个双字词、6 个自然改写和相似编号、版本号、直接问法及无答案问题。16 个标注证据目标按独立事实编号，同一事实的记忆和原文共用证据编号。每组用同一语料、历史截点、标注、上下文预算和去重方式。截点之后有一条故意放入的错误未来记录，不参与任一组。无答案组含 6 问，包括不存在的近似编号。

在 asHub 根目录使用项目固定的 Node 版本。词项对照不需要额外依赖：

```sh
node benchmarks/personal-assistant/recall-zh.mjs
npm run build
node benchmarks/personal-assistant/host-pressure.mjs
node benchmarks/personal-assistant/host-pressure.mjs --varied
```

语义对照使用 BAAI 公开的 [BGE-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 权重、CPU 4 线程、512 维归一化 CLS 向量。仅使用合成语料。Python 程序加载本地 safetensors 并校验模型 SHA-256，运行时不联网，也不读取真实对话。可从 Hugging Face 的同名模型仓库下载这些公开文件；以下是本次可用的 ModelScope 镜像：

```sh
model_dir="$(mktemp -d)"
for model_file in config.json tokenizer_config.json special_tokens_map.json vocab.txt tokenizer.json model.safetensors; do
  curl -fLsS "https://www.modelscope.cn/models/BAAI/bge-small-zh-v1.5/resolve/master/$model_file" -o "$model_dir/$model_file" || break
done
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 uv run --no-project --python 3.12 \
  --with 'torch==2.9.1' --with 'transformers==4.57.6' \
  python benchmarks/personal-assistant/local-embedding.py "$model_dir" > /tmp/ashub-recall-zh.json
```

JSON 带逐题标注、注入的证据 ID 及语义模型前三名的相似度。无关占位统计所有不在该题标注中的注入条目，包括有正确答案的题；无答案误召回统计 6 个负例中有任何注入的题数；重复占位按同一证据额外占用的条目计算。排序微基准 P95 是预热后每题 12 次排序和选择，不含宿主历史读取、网络、生成模型调用。语义组加上每题 5 次向量编码和相似度计算的中位数；不含首次加载和语料向量构建。真实宿主压力另用临时 SessionStore、实际授权服务、真实请求注入代码测量，每组预热 8 次后测 60 次。

同一小样本的阈值探索见下表。语义候选至多 2 条，需同时过绝对阈值、距当前最高分不超过 0.04；精确编号类不使用语义补位。语义实验依赖不进入 asHub 或插件包，不能把样本结果视为生产召回率。建议复核独立留出集的自然改写、硬负例、近似值和较长历史，再决定是否加入可选本地索引。

| 方案 | 找回证据 | 无关占位 | 重复占位 | 无答案误召回 | 排序 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 现状 | 3/16 | 4 | 0 | 1/6 | 0.12 ms |
| FTS5 混合 | 10/16 | 2 | 0 | 0/6 | 0.41 ms |
| 混合 + 本地语义，阈值 0.60 | 10/16 | 2 | 0 | 0/6 | 3.34 ms |
| 阈值 0.55 | 12/16 | 2 | 0 | 0/6 | 3.34 ms |
| 阈值 0.50 | 14/16 | 2 | 0 | 0/6 | 3.38 ms |
| 阈值 0.48 | 15/16 | 2 | 0 | 0/6 | 3.28 ms |
| 阈值 0.45 | 15/16 | 3 | 0 | 0/6 | 3.41 ms |
| 阈值 0.40 | 15/16 | 5 | 0 | 1/6 | 3.36 ms |

词项混合从双字词的 0/4 提升至 4/4，三条有答案的精确编号从 1/3 提升至 3/3；6 个自然改写在阈值 0.50 的语义组命中 4 个，在词项组命中 0 个。近似编号和版本没有串号。模型权重约 91.4 MiB，加载加本语料向量构建约 71 ms。压测包括 40 条长用户消息和 1 条待遗忘消息：在平均 2292 字符、不同片段的场景，开关遗忘规则前后真实宿主 P95 分别为约 29 ms 和 32 ms；重复片段场景约 8 ms 和 11 ms。结果是本次 arm64 Mac 的本机测量，宿主压测没有调用模型或网络。

## 第二阶段：中文事件和后台整理对照

```sh
npm run build
node benchmarks/personal-assistant/events-zh.mjs
npm run test:personal-assistant
npm run test:personal-assistant:ui
```

使用项目固定 Node 版本。该脚本用临时 SessionStore 与真实插件授权宿主，每组独立重建相同语料。两组共用二阶段的写入安全校验、持久化、授权与游标；对照组是在同一二阶段代码上关闭分段和增量筛选的消融，不是旧版实测。模拟时钟同时控制 Date 构造与 Date.now，固定每个 UTC 日最多 4 个请求，与真实默认额度一致。模拟模型只按固定标注返回结果；若未收到正确的旧条目版本，则不返回修订。数字反映候选提供和调度行为，不衡量真实模型的抽取正确率或实际 token 账单。

| 方案 | 后台调用 | 序列化请求总字符 | 单次最大字符 | 旧记忆候选占位 | 按编号原地修订 |
| --- | ---: | ---: | ---: | ---: | --- |
| 关闭分段与增量筛选 | 7 | 49,473 | 7,359 | 56 | 未提供目标旧 ID |
| 事件分段 + 选择性巩固 | 5 | 30,686 | 8,044 | 12 | 保留原 ID 完成修订 |

同一批中有两个无关话题和一条编号纠正。关闭分段时该批有 8 条旧候选、0 条原文出处，没有选中纠正对象；打开后分成 3 个事件，提供 6 条附出处的旧候选，号码只在旧原文中出现也能对齐正确 ID。该批请求因附证变长，仍低于 16,000 字符。两组都能用隔日独立证据推进观察条目，且共用的完整来源去重规则会拦住同一原文换截引的重复支持。新版另外跳过一次性事项和确认过的独立重复原文，无须调用模型。序列还检查临时例外、未解决冲突、旧证据迟到、问句先到后跨批/重启的短答、遗忘和撤权；逐步指标会输出为 JSON。授权中途撤销、忘记的在途回执、分支回退、精确编号与多人名场景另见 `tests/assistant-dedicated.mjs` 与插件的 `tests/events.mjs`。

## 3A 规模化召回的验收口径

规模对照只用临时数据库和合成会话。同一份语料、权限、活动分支和请求分别跑旧全扫描与默认入口；除了耗时，还比较入选证据、注入预算、各入口取出的完整候选数及逐条验证器调用数；这不是宿主 API 请求数。若对照和新路径共用已优化宿主，应标明这是只比较候选检索的消融；旧宿主的端到端数据不与该消融混算。

兼容性复查包括两条路径：旧库直接升级，以及升级后回退、在旧版新增或改写记忆、再升级。两条路径都要保留记忆 ID、证据、遗忘和授权，并验证纯概念及通用回复偏好无需字面命中也可召回。实际 ZIP 安装和默认会话请求均应覆盖，独立测试用的全扫描入口不应成为日常召回路径。


```sh
npm run build
node benchmarks/personal-assistant/recall-scale.mjs --runs 10
# 比较候选路径：阶段二插件和 3A 插件共用当前编译好的宿主
node benchmarks/personal-assistant/recall-scale.mjs --root "$phase2" --host-root "$PWD" --runs 10
# 比较完整端到端：阶段二目录须有自己的完整 dist
node benchmarks/personal-assistant/recall-scale.mjs --root "$phase2" --runs 10
```

`phase2` 指阶段二源码或验收快照。只测一档可加 `--memories 1000 --history 10000`。默认矩阵为 100、500、1000 条稳定记忆乘以 1000、10000、50000 条历史；每档覆盖 7 种查询。脚本的 `cold` 是数据库已打开且填入数据后每类查询的首次请求，不包含数据库派生索引初次重建。`warm` 统计同一进程的重复请求。候选对照固定取最多 12 条，窗口 12/24 是每批来源校验的候选条数，默认 24；不是 FTS 总候选上限，也不是最终注入条数。分入口提取的候选数可能包含重叠行，实际逐条验证次数单独输出。所有过程使用合成语料，未调用模型。

在 1000 条记忆 / 10000 条历史档，共用优化后宿主的九组测量中，该档的对照为（测量后补了预算边界的回归）：

| 查询路径 | 热 P50 | 热 P95 |
| --- | ---: | ---: |
| 阶段二全扫描 | 28.02 ms | 30.83 ms |
| 3A 默认入口 | 1.66 ms | 16.17 ms |

该档 7 种查询都找回了标注证据。逐条验证器在阶段二每种查询调用 1000 次，3A 候选对照中为 1–12 次。3A 的密集查询热 P50 为 15.98 ms；大量稳定记忆命中同一组词时，仍需处理较大的候选集合。以上数字不与不同机器或未优化宿主的端到端测量混算。


## 3B 主题概览试点的验证口径

```sh
npm run build
node benchmarks/personal-assistant/theme-overviews.mjs --trajectories 40
node benchmarks/personal-assistant/theme-overviews.mjs --root "$phase3a" --host-root "$PWD" --trajectories 40
```

两组共用当前宿主、40 份合成会话和 240 个查询。其中 20 个助手对话未归属项目。预置概览的查询验证能否按范围召回和核对证据。3A 基线没有概览功能。

| 指标 | 3A | 3B 试点 |
| --- | ---: | ---: |
| 项目历史问题召回概览 | 0/40 | 40/40 |
| 协作偏好问题召回概览 | 0/40 | 40/40 |
| 精确编号问题召回正确证据 | 40/40 | 40/40 |
| 无关、其他项目或同名歧义误注入概览 | 0/120 | 0/120 |

另用 4 份各含 22 条决策的会话运行后台整理。每份调用一次模拟模型，最早的原则与最新转折均进入候选、保存并成功召回。回归测试另外验证证据区间、撤权、遗忘、固定模型授权、改名复用、重启和关闭试点。所有测量都使用合成材料和本地替身，未调用真实提供商。结果只反映实现能否按预设证据运行，试点仍需显式开启。
