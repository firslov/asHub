# ScreenCaptureKit 验证记录 · 2026-10-26

实现位于独立 desktop-control 插件内，不修改 asHub 主程序或已安装的 arc-cua。辅助程序按 Intel 与 Apple Silicon 两种架构编译，保留指定窗口与进程绑定、任务授权、截图坐标换算和取消检查。

## 已确认

- 本机微信 4.1.15 主窗口 sharing state 为 0，用户确认它在另一台显示器上正常可见。
- 单窗口 ScreenCaptureKit 路径返回空白；显示器内仅包含该窗口、按边界裁剪并刷新流的路径同样未取得有效帧。
- captureImage 接口返回请求尺寸的一半；改为读取 sample buffer 后得到正确的 880×657 尺寸，但正确尺寸不等于捕获到微信内容。
- 已加入黑图、透明图及纯色空图检测，明确区分捕获失败和 OCR 布局不支持。错误不自动归因为缺少权限或微信保护机制。
- 没有移动微信窗口，没有输入或发送微信消息，没有自动修改插件配置。

## 前台区域验证结果

经用户授权测试前台可见矩形截取；用户将微信从主屏移到副屏后，重新核对了同一进程和窗口的位置。区域截取返回 880×657 图像，但核验发现实际内容为微信后面的 ChatGPT 页面。OCR 得到 8 行文字，却没有微信布局锚点；不能把接口成功、图像非空或 OCR 有文字等同于成功读取目标应用。

因此前台区域路径未通过验证，不纳入插件发布包，不用于自动导航或发送。实验源文件仅留在开发目录 diagnostics，既不是自动回退路径，也不向插件用户开放该选项。结束本轮实机尝试，不再重复截图。

当前交付只包含可选的指定窗口 ScreenCaptureKit 组件与更明确的捕获诊断。默认仍为 legacy 截图路径；未修改当前用户配置。微信在本机的可靠捕获问题仍未解决，不能宣称发送已修复；根因尚不能从 sharing state 或上述结果单独确定。

后续应先在人工确认的微信画面上验证目标窗口图像、布局与身份，再单独进行经用户授权的收发验收。不能用捕获到的底层应用图像代替微信核验。
