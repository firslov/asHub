# Kimi Coding Plan for asHub

独立 provider 插件，支持官方网页授权登录，也可复用本机 Kimi Code 登录，或使用 Coding Plan API Key。无需修改 asHub / agent-sh 核心代码。

## 安装与使用

1. asHub → 插件 → 安装插件，选择 `ashub-kimi-coding-plan-0.2.1.zip`。安装器自动安装锁定的 npm 依赖，无安装脚本。
2. 在对话中输入 `/kimi-login`，浏览器会打开 Kimi 官方授权页。登录并确认授权后，插件自动保存凭据、刷新模型；`/kimi-login cancel` 可取消。也可直接复用本机官方 Kimi Code CLI 的 `kimi login` 登录，无需复制凭据。账号需具备 Kimi Coding Plan 权益，网页登录成功不代表拥有套餐权限。
3. 新开对话，或在空闲对话中重新加载插件。模型选择器选择 provider `kimi-coding-plan` 下的模型。
4. `/kimi-status` 查看状态；登录更新或模型变化后运行 `/kimi-refresh`。这些命令需要启用内置斜杠命令组件；关闭该组件不影响模型使用，可通过插件菜单重新加载。

插件不会主动读取或发送已有对话。只有选用此 provider 的模型请求会发送给 Kimi。登录凭据只发往官方 Kimi API／认证域名，刷新后原子更新原凭据文件，失败不删除原登录。

可选 API Key：启动 asHub 的进程环境中设置 `KIMI_API_KEY`，或兼容的 `MOONSHOT_API_KEY`。必须使用 **Coding Plan** 的 Key，并非普通开放平台 Key；环境变量优先于本机登录。存在这类环境变量时，`/kimi-login` 会提示先移除它们并重启，避免网页授权成功却仍使用旧 Key。勿将密钥写入插件源码或分享的安装包。

## 配置

插件配置命名空间为 `kimi-coding-plan`，默认无需修改：

```json
{"kimiHome":"","effort":"default"}
```

- `kimiHome`：留空自动发现 `~/.kimi-code`，兼容旧的 `~/.kimi`；也支持 `KIMI_CODE_HOME`。如使用其他目录，填写绝对路径。
- `effort`：`default` 使用服务端默认。可选 `low`、`high`、`max`；`off` 仅用于接口明确支持关闭思考的模型。模型不支持时会明确报错，不偷偷替换等级。
- 当前 asHub 的通用思考选择器尚未开放插件自定义等级，因此本插件不启用该选择器。通过本插件配置设置思考强度，保存后按 asHub 提示重新加载插件。建议保持 `default`，尤其是切换到无可调等级的高速模型时。

模型列表、上下文长度、图像及思考能力从账号的 `/models` 接口动态发现，不写死 PR 中的旧模型别名。接口未提供输出上限时，保守限制为 32,768 tokens；这不是对模型最大输出能力的声明。

## 登录与错误提示

- `/kimi-login`：官方设备授权流程；浏览器确认后保存登录。需要切换账号时重新运行。
- `/kimi-login cancel`：取消当前会话发起的登录，插件停用或会话关闭也会取消；不会删除已有登录。
- 网页登录成功后，会等待旧账号正在进行的模型刷新结束，再使用新凭据读取模型，避免切换账号后仍显示旧模型列表。取消或关闭会话不会继续触发登录后的更新。
- `/kimi-status`：显示认证方式、模型、登录等待状态及最近一次权限错误。
- 网页登录与 CLI 复用同一个凭据文件，因此重新授权会更新 CLI 后续使用的账号。保存与刷新共用文件锁，防止互相覆盖。
- 当前内核会把 401 和 403 统一显示为“Check your API key”。插件保留正确 HTTP 状态，同时在对话中补充登录失效或套餐权限不足的独立提示；不会通过修改状态码掩盖错误。403 需要检查 Kimi 官方账号的套餐／模型权限，反复登录不一定能解决。

## 行为与边界

- 保留原生流式协议、工具调用、图片消息和工具轮次中的 `reasoning_content`。
- 本地适配器只监听 `127.0.0.1`，使用随机认证密钥，拒绝浏览器 Origin 请求；插件停用时关闭监听并取消请求。
- 保留 asHub 对话的网络代理上下文；不修改系统代理。启动发现有时间上限，离线不会无限等待；网络恢复后可 `/kimi-refresh`。
- 本地登录失效及 OAuth `invalid_grant` 会明确提示重新登录，不再伪装为可重试的网络故障；服务端限流等待及重试提示会传递给 SDK。
- OAuth 401 最多刷新重试一次。403 不重试，提示检查套餐／模型权限；429 不在插件内循环重试。传输失败仍受 asHub / SDK 自身重试策略管理。
- 等待上游响应头上限 120 秒，流式空闲上限 5 分钟；取消操作及时终止调用。
- 与新版 Kimi CLI 使用相同凭据文件及刷新锁。不要在多个工具执行请求时反复登录／退出登录。
