# 个人助手 · 0.3.6

一个在后台维护长期记忆的 asHub 插件。一次授权后，自动整理有价值的用户偏好、纠正和决定，在相关对话中按需召回；无需逐条手工确认。学习策略、存储、检索和面板都属于插件，宿主只提供通用授权、历史读取与隔离模型调用。

## 安装与开始

需要包含 `plugin-data` 和 `background-services` 能力的 asHub 源码版本及 Node >=22.13。已发布的 0.21.1 不支持本插件，旧宿主会在安装前提示不兼容。ZIP 不需要安装 npm/Python 依赖。

1. 在插件菜单加载 ZIP，升级后重启 asHub，避免旧模块仍驻留内存。
2. 打开右侧「个人助手」，点击「开启助手」。首次仅需选择整理模型；优先复用此前选择，只有一个可用模型来源时自动选中。每日默认最多 4 次整理，已有授权额度保持不变。
3. 排除对话、是否整理已有历史折叠在「高级选项」中，默认仅观察新消息。查看宿主给出的范围、模型和成本后确认授权。
4. 日常面板只有「暂停／继续」和「查看记忆」。暂停同时停止学习和召回，保留记忆与授权；继续沿用原额度及读取进度。
5. 「查看记忆」集中展示可用、观察中和历史记录，可搜索、查看来源或忘记。不再展示手动关联、添加记忆、逐条确认、成长管理等配置入口，也不会引导模型要求用户逐条审批。
6. 需要调整授权时，暂停后通过说明区域的「更多 → 重新设置授权」进入；模型不可用等授权问题也会显示此入口。

授权模型来源被删除或更换模型/provider/工作目录后，需重新授权。后台请求独立于正常对话，不执行工具、不添加聊天记录，不修改会话系统提示词或压缩策略。

## 学习、召回与自我改进

- 按持久化记录 ID 增量读取活动 agent 对话，不逐 token 扫描。归档会话、终端、附件正文目前不读取；自动生成的跨对话任务与工具输出不作为用户记忆证据。
- 整理模型提出带用户原文引用的条目；插件核验来源 ID 和引用是否真实存在。明确偏好、原则和事实可自动生效；推测需要独立证据，明确的职业、专业、年龄等个人事实也可形成全局记忆；项目结论保留项目背景和适用条件，不提升为无条件个人原则。
- 旧版模型提案会自动进入原文核验：保留原 ID 和版本，用授权范围内真实用户消息重新验证；依据明确的事实/偏好/原则成为正式记忆，推测和方法继续遵循原有证据门槛。不自动覆盖用户确认的记忆或旧修订提案。状态统一显示“观察中 / 正式记忆”，无人工确认要求。
- 旧候选也会利用新增消息核验；没有新消息时，后台增量回查授权范围内的持久化历史，与普通整理共用每日额度，保留读取进度。若原授权不包含旧历史、来源被归档或排除，旧依据不可读取，候选可能继续观察；不会扩大权限或反复消耗额度重读同一批内容。大量候选会分批处理。
- 同一用户主题可以跨对话更新，并保留版本；按原始证据时间判断先后，后补录的旧历史不会覆盖更新的纠正；结论未变时仍可补充独立证据，并保留最新来源信息。用户手动定稿不被后台覆盖；忘记后相同主题不会自动复活；若整理请求已经发出，返回结果在保存前仍会重新核对遗忘状态，不接纳来自已忽略原文的改写、候选核验或反馈。
- 经验与流程先保持“观察中”，不能仅靠模型自评或重复同一句话生效。至少两次独立、发生在原始依据之后的明确用户正面反馈（按消息时间判断，不按补录入库时间）才自动进入可用记忆；负面反馈会撤下相应方法，避免继续套用。这里表示“获得用户反馈支持”，不等于客观实验已经证明有效。
- 同一用户/profile 共用一个全局记忆库，不以来源会话为检索边界。召回使用本地中文词组/Unicode 词项、常见个人背景问法和整理时生成的检索别名。自动召回按相关性筛选，最多 4 条，通用表达偏好最多 2 条；无关问题不注入个人档案。其他项目的具体结论默认不自动带入，明确提到该项目或条目标题时才纳入；显式搜索仍可跨项目发现它们。没有网络 embedding，也不宣称已实现向量语义检索。
- 注入是请求级副本，保留图片与工具调用 ID，不改写原历史。条目总预算 2400 字符，另有少量包装；后台与面板摘要按 Unicode 安全边界截取，不切断 emoji，完整原文保留；保留主体、来源背景与证据时间。年龄等按当时自述理解，不推算生日。未覆盖内容可按需 search/read；涉及用户背景或过去决定时，模型在回答“不知道”前应先搜索一次。
- 来源仍为活动对话时，检查证据是否仍在当前历史分支；回退后的证据不参与召回。来源归档或删除不会自动删除已经核验形成的长期记忆，若需删除记忆请使用“忘记”。明确排除的对话既不使用全局记忆，其产生的记忆也不参与召回；暂停及撤销授权继续生效。

## 开销与限制

- 默认每天最多 4 次整理，可选 1–24 次，按 UTC 日期计数。每次请求按最终 JSON 序列化结果限制为最多 16000 字符，输出预算 4096 tokens，超时 60 秒。失败和取消的已发起请求也计入次数；额度耗尽会等待后续日期。
- 每分钟最多处理一个有内容的批次，只读取新增记录，正常对话忙碌时避让。单个对话历史读取失败时保留原进度并轮换，不阻塞其他对话或旧候选的整理。大量历史或对话可能需要多日逐步消化，不承诺实时记住每句话。
- 每条历史记录最多整理前 3000 字符；转义后超过请求预算时进一步缩短该条前缀，不跳过后续消息。正文过长或超过额度的内容可能暂未形成记忆。短期闲聊通常不保留。
- 检索不发起模型调用；后台整理会把授权消息发送给所选模型服务，可能产生费用。常见密钥格式会过滤，但不能保证识别所有敏感信息，请排除不希望观察的对话。
- 来源核验能防止虚构引用，不能证明模型的解释一定正确。用户当前要求优先于历史记忆；可以随时纠正或忘记。
- 当前“自我改进”限于记忆修订和有反馈依据的方法积累，不自动修改代码、安装插件、扩大权限或启动长期委托。其他插件能力继续使用它们各自的授权流程。

## 数据与生命周期

SQLite 位于宿主 package/profile 隔离的数据目录；升级保留已有记忆、手动关联和版本。旧 `scope` 字段保留为来源/适用背景，读取时兼容转换，不重写原记录或要求重新整理历史。内容一致、背景相同的重复条目只召回一份；同一句话中不同的事实仍会保留。原条目和版本仍可查看，不基于猜测批量删除内容。事务和修订号避免并发覆盖。最多 1000 条可用、100 条候选、10000 条总记录，每条保留 10 个版本。

暂停后台学习或停用插件会取消相关后台请求并停止新学习。使用主界面的暂停开关时，自动条目与手工条目都停止新的召回；已有上下文不被改写。应用关闭后不会继续运行，后台运行依赖 asHub 守护模式。

忘记会移除正文、检索索引与版本，保留去重指纹和必要来源 ID。原聊天、已发送给模型的上下文和用户备份不受影响；不是磁盘取证级擦除。来源原文只展示在本机管理面板，不随个人记忆跨项目发送；模型工具仅返回记忆内容及来源 ID 等元信息。

插件是可信本地 JavaScript，并非恶意代码沙箱。远控聊天通过桌面内核使用同样的召回；手机端插件管理面板暂未加入。

## 验证

插件目录运行 `node --test tests/*.mjs`；仓库运行 `npm run test:personal-assistant` 和 `npm run test:personal-assistant:ui`。测试使用临时数据、隔离内核和模拟模型，验证安装、授权、学习、来源、反馈、取消、重启和界面，不读取私人历史或调用付费模型。真实语义提取质量与账单开销仍需上线使用后观察。
