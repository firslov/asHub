# 个人助手

一个常驻的专属对话，在持续交流中逐渐了解你。只从这段对话整理与召回记忆，普通对话不会自动参与。

需要本次配套的 asHub 主程序与远控网页。宿主须支持 `conversation-scoped-sessions` 和 `project-name-history`。后台服务在应用层运行，会话入口仅加载到绑定的个人助手对话。安装配套主程序和插件后重启 asHub，使已有会话使用新版接口。

## 开始使用

自 asHub 0.21.10 起，本插件随发行版提供。首次使用请在「插件 → 本地扩展」启用，无需另装 ZIP；启用插件不会自动开启记忆或授予后台模型权限。升级主程序时，已有手动安装仍优先使用，保留原安装和启用状态。卸载随附插件后，升级不会自动恢复；可按需在本地扩展列表重新安装。

安装启用后，左侧出现常驻个人助手入口。首次选择聊天模型，可选择是否自动记住重要信息；确认后直接进入聊天。开启记忆时会在后台自动整理。模型、思考强度和 VPN 使用对话原有控件。已授权记忆后，桌面助手入口的「对话选项」可管理默认关闭的主题概览试点。

点击个人助手入口右侧的「···」管理记忆。设置中显示当前整理状态或最近整理时间。额度用完或连续失败时以执行设备的本地时间提示何时可以继续，实际整理仍需等待对话空闲。桌面和远控复用同一插件输出，读取状态不调用模型。「最近整理」表示批次处理成功。对话中的状态工具可查询最后成功时间、是否待处理及重试状态。开启时需要确认授权，关闭立即生效。你也可以直接在对话中说“记住……”或“忘记……”。关闭后停止学习和召回，保留记录。

首次确认明确授权后台跟随该对话当前及今后选择的模型和 VPN，只读取助手对话。旧的固定模型授权不会自动扩大，如需改用跟随模式，可通过入口开关关闭记忆后重新开启并确认授权。记忆失败或额度耗尽只暂缓整理，已有记忆仍可使用。

## 记忆如何工作

- **原始经历**：复用专属对话的持久化历史与分支 ID，不复制或扫描其他会话。记忆不足时可按需搜索原文，再分段读取核对。回退撤销的来源不参与召回；新分支提供有效依据后重新整理，不继承已撤回的来源和验证反馈。
- **证据条目**：每条自动记忆附带真实用户原文、来源 ID、时间及主体；模型自己的判断、转发任务和外部材料不能作为用户陈述的证据。当前纠正优先于旧记忆。
- **认识更新**：按 ID 与版本补充、修订或否定记忆。同一范围内的相同命题合并证据，同主题但关系不明的内容继续观察。以最新的明确用户陈述为准，核对证据所在句子的临时限定。
- **克制召回**：稳定记忆用 SQLite FTS5 按中文词项、精确编号、既有概念和回复风格筛选候选，再按批次核验授权及出处。注入按实际剩余预算补位，不让失效来源或装不下的大条目占用名额。派生索引可从既有记忆重建，不改变记忆 ID、授权或遗忘状态。剩余预算可补近期授权用户原文，单次最多 2 段；标注其来源、时间和未经整理，不把原文、引用或假设当成稳定事实。报告编号、常见版本号（可带 `v`）和 IPv4 地址按完整词项匹配。IPv4 可按主机查询，明确写端口时要求端口一致；不进行 URL 路径、IPv6 或域名语义检索。当前请求已包含的近期原文不重复注入，已修订记忆的旧来源不与新版本一同自动注入，可按需显式核查。长消息在固定检索预算内保留首尾，简短追问可借用一个邻近用户回合。自动注入可以为零，最多 4 条、条目总计 2400 字符，保留原正文、图片和工具调用 ID。
- **事件证据**：整理时按对话切换、间隔和词项连续性分组；同一条消息可以有多个片段，每段带原消息 ID 与 UTF-16 区间。相邻问答在分段或续读时可带前问作只读参考。精确编号和中文词项也会用于筛选旧证据，最多提供 8 条旧记忆，每条最多附一个短原文。明确纠正优先获得候选预算。事件在授权批次内按需计算，不另建持久原文索引，不调用额外模型。
- **证据巩固**：用用户完整来源去重，同一消息换引文、隔日重放不会再增加支持；独立的新观察可以补到既有记忆。明确纠正按旧条目 ID、版本和证据顺序修订；临时限定不能覆盖或支持长期规则，未定冲突只作为观察。前问从分支或授权中消失时，依赖它的短答案不能单独继续作为证据。同一遗忘值明确出现在仅依赖短答上下文的派生记忆时，会一并撤回。
- **增量整理**：空闲时处理新记录，单个批次至多 6 条记忆。同一授权范围重新开启时沿用有效进度，每次读取仍核对新授权和当前分支。明确偏好和事实可直接生效；推测继续观察；经验与流程需要独立的后续用户效果反馈，明确反例会停用。自我改进限于这些有证据的记忆修订和方法积累，不自行改代码、扩权或安装插件。

主题概览试点整理能核对出处的项目决策和跨事件协作偏好。开启时沿用专属助手对话已授权的模型与范围。每天最多 4 次后台整理中，主题最多占 1 次（UTC），普通证据和纠正优先。自动召回时概览至多占 1 条，与其他记忆共用 4 条、合计 2400 字符的预算，原文最多 2 段。插件按原文时间和当时可核实的项目名称判断归属。名称记录不完整的日期内，原文和普通记忆仍可按授权召回，项目概览暂不归因。整理时在同一次后台调用中，让模型结合候选原文和同一授权对话中的相关用户原文，区分已成立、带条件、被否认和证据不足。邻近证据仍按后续 3 页和 7 天范围读取。超出范围的更新可通过当前授权分支的原文索引，按工单编号或同一项目的主题关联定位。相关证据变化时，旧概览暂缓召回，等后台重审。关联证据过多或无法完整核对时，概览暂缓展示，仍可按授权查阅原文。已成立的决定要有可在候选原文中唯一定位的承诺片段。概览保留完整原文及其条件，单独的需求、目标和仍未选定的方案留在普通记忆或原文中。候选按批次推进，既有概览在各项目后续整理时逐步重审。新条目只保存上下文的来源引用与摘要，召回时检查原文、归属、授权和遗忘状态，无需再调用模型。单独关闭试点会取消在途主题整理并清除派生内容。关闭长期记忆也会关闭试点。手机端可在个人助手的「···」中关闭记忆。

设计参考 Anthropic 的 [Components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)：原始经历、结构化记忆、检索与离线整理。本文描述的是 asHub 的具体实现，不声称复刻 Claude 内部架构。

## 界面与手机

桌面与手机复用同一对话和本机记忆库，手机不独立执行整理。远控端只提供关闭长期记忆；首次创建和开启授权仍需在桌面确认。电脑离线时不能使用手机继续访问该助手。

移动访问仍遵循现有目录授权：若手机没有出现助手，请在桌面「移动访问」共享创建时展示的助手工作目录（插件数据目录下的 `workspace`）。不会为了让入口出现而自动扩大目录授权。远控网站也需部署本次配套版本；旧桌面未声明能力时不显示新入口。

## 升级、暂停与恢复

- 首次升级停止旧的全局后台学习并解除旧手动关联。原数据库和记忆保留，不默认迁入新助手。
- 暂停记忆停止新增学习和召回，已有聊天与记忆保留。重新启用需要确认授权。新的跟随授权会沿用对话当前模型和 VPN；旧固定模型授权不会自动扩大。
- 插件停用会隐藏入口并取消后台整理。重新启用仍指向同一对话；如果原对话已删除或创建中断，下次创建须重新确认，并明确提示会新建对话。
- 应用退出后不会继续整理；需要常驻时使用 asHub 后台守护模式。

升级插件时保留包名和安装入口，使用现有安装流程替换同一路径，不手动搬动插件目录。卸载保留的聊天和记忆不是自动安装依据；显式重装到原路径后可恢复原身份与数据。内核只保存通用会话绑定和授权，记忆数据库、迁移及整理恢复由插件管理。

主题概览放在独立的派生数据表。回退到旧版仍可使用普通记忆。再次升级时会核对原文、记忆版本和当前授权，旧版期间的纠正、遗忘或记忆关闭也会生效。

## 成本与限制

默认每日最多 4 次后台模型请求，按 UTC 日期计数；每次序列化输入不超过 16000 字符，输出预算 4096 tokens。失败和取消的已发起请求也计入额度。每分钟至多一批，忙碌时避让，新近记录等待至少 90 秒。每日额度按插件累计，关闭、重开和重启不重置。短暂故障采用有界退避，额度用完等待下一个 UTC 日期。显式「记住」使用现有对话工具调用，不额外启动整理模型。

在桌面端打开个人助手的「··· → 整理模型」，可跟随对话模型，也可从已配置的提供商中指定一个整理模型。确认时会显示接收授权原文的模型服务和共享额度。切换后保留聊天模型、历史授权与当天已用次数。指定模型服务的地址变化后，可从同一入口重新确认。提供商不可用时，已有记忆仍可召回。

宿主 `background.status` 的 `calls` 是当天的后台派发次数。提供商返回用量时，宿主累计 `tokenUsage` 中的输入、输出 tokens 与有用量回报的请求数。模型费用和完整账单以提供商记录为准。

长历史可能需多日消化，每条记录按 3000 字符以内的片段增量处理，持久保存消息 ID 与偏移，长文尾部可在后续批次继续；可结合紧邻问题理解简短回答。预算不足时保留进度，原文工具仍可分段读取。原文自动召回仅遍历当前活动分支近期最多 96 个记录，扫描文本累计至多 120000 字符，单条超过 12000 字符暂不自动注入。原文 FTS 索引只在请求期间留在本机内存，索引不可用时仅召回符合现有授权和来源验证规则的稳定记忆。没有在线向量服务；本地语义检索只在仓库的合成样本实验中运行。常见密钥格式会过滤，但无法识别全部敏感信息。原文依据只能核实出处，不能证明模型解释必然正确。

SQLite 保存在本机、按安装包/用户配置隔离。最多 1000 条正式记忆、100 条观察记录和 10000 条总记录，每条最多保留 10 个版本。事务和版本检查防止覆盖并发编辑。候选池满时仅归档弱、旧的自动假设，原记录和版本保留；正式记忆不会静默删除。无法立即保存的新结果进入有界延期队列，避免阻塞独立事实或反复调用模型。

「忘记」清除正文、索引和版本，保留不可逆去重指纹与必要来源 ID，避免从同一证据再次学习。遗忘后如需重新保存，请在助手对话中直接说「请重新记住：完整内容」；仅接受遗忘之后当前用户的明确正向请求及完整原文，转述、引用、疑问和否定不会解除遗忘，不恢复旧记录或旧来源。原文召回还会屏蔽重复出现在新消息中的完整遗忘证据和精确编号，不仅按原消息 ID 排除。它可识别常见的人称复述，不能识别任意重写或推断。常见短确认词不单独建立遗忘规则；有歧义的短证据可能挡住含同一字串的原文，但不会过滤独立稳定记忆。旧版若只记录来源 ID，且无法在当前分支与授权内核对该来源，自动和显式原文召回暂时回退；能验证的独立记忆仍可用。如果需要用遗忘规则核验超长原文，不能完整核验时不提供该原文。相关学习恢复缓存一并清理。原聊天、已发送给模型的上下文与外部备份不受影响。不是磁盘取证级擦除。手机响应仅作短期内存缓存，不加入 PWA 静态缓存或通用持久回执日志。

## 验证

```sh
npm run test:personal-assistant
npm run test:personal-assistant:ui
node --test tests/plugin-interactions.cjs tests/regression-remote-connector.mjs
# 在 remote 目录配置 Playwright 后
node remote/render-assistant.cjs
# 插件状态回归：需 Playwright Chromium / WebKit，可用 PLAYWRIGHT_MODULE 指定安装路径
npm --prefix examples/extensions/personal-assistant run test:ui
```

覆盖专属对话隔离、原文检索、重复创建、升级迁移、暂停与重启、遗忘、原文代理对边界、真实内核召回、真实 HTTP 授权、远控幂等/撤权以及桌面和 320/390px 手机布局。

对话内遗忘需要明确指定记忆标题、完整内容、来源原文或 ID；名称匹配多条记录时，助手会请你说明要忘记的具体内容。重新记住只保存本次明确请求的内容，不用其他事项的指令恢复旧记忆。

授权页只展示读取范围、后台模型与使用额度。已有聊天及后续消息的边界合并在读取范围中，不显示对话编号、重复字段或空的排除列表；「授权详情」仅保留单次整理额度。展示精简不改变实际授权范围。

本版本需要配套更新 asHub 核心才能获得一次确认、模型跟随、Codex 后台 VPN 和远控资源 ID 修复。插件要求宿主声明 `conversation-resource-popovers` 能力；旧宿主会拒绝安装此版本，请先升级主程序，或继续使用原插件。

后台调用账本使用新版宿主存储格式。升级可迁移旧授权中仍保留的调用次数；旧版已经删除的记录无法追溯。回退到不支持新版账本的宿主时，后台授权会停止使用，不会静默重置额度。

分段续读适用于升级后的处理进度；不会为了补旧版已越过的长消息而自动全量重扫历史。旧内容仍可在对话中通过原文工具检索。

第二阶段的主题边界和临时措辞检测是有界的启发式规则。它不能判准所有话题变化或区分任意语义改写；模型需要引用确切的新用户原文，旧证据只是参考。完整来源过长而无法有界核验时，不能仅靠不同截引把它算成多份独立证据。中文控制对照参见仓库的 `benchmarks/personal-assistant/README.md`。
