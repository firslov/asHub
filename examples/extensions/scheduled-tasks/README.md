# asHub 定时任务

到达指定时间后，向已有对话提交一条任务消息。调度与任务界面由插件实现，asHub 仅提供通用授权、消息投递和插件界面能力。无需 crontab、额外运行环境或 npm 依赖。

## 安装与使用

需要包含 `plugin-resources` 与 `authorized-messages` 能力的新版 asHub 本地构建。**现有 0.21.0 正式安装包尚不具备这两个接口**；请先构建并启动本次修改后的 asHub，再从「插件」菜单导入 `ashub-scheduled-tasks-0.1.1.zip`。旧宿主会拒绝安装，不会降级绕过授权。

启用后，右侧出现时钟按钮：

1. 点击「新建任务」，选择目标对话，填写任务名称和执行内容。
2. 选择单次、每天、工作日、每周或固定间隔。时间按任务保存的时区计算。
3. 检查预览中的时间规则、目标对话、消息正文和权限范围，点击「确认」后生效。
4. 在任务的「更多」菜单中编辑、暂停、恢复、立即执行一次、查看运行记录或删除。历史记录可打开目标对话。

首次创建不会立即执行。立即执行一次需要单独确认，不改变原定时计划。修改或恢复也会重新确认消息授权。任务列表与编辑界面采用 asHub 的通用抽屉、表单、颜色和字体。

## 示例：每天 9 点打卡

先选择一个已配置好桌面控制插件、能访问目标网站的对话，设定每天 `09:00`，再填写：

> 打开指定网站，先检查今日是否已打卡；已完成则跳过，否则打卡一次并核验成功提示。登录失效、出现验证码或无法确认结果时停止并说明，不重复提交。

将「指定网站」改成实际网址。定时授权只允许提交这条消息，**不会自动授予桌面控制、发送消息、登录或其他工具权限**。所需工具仍按自身的授权规则运行。

## 执行规则

- asHub 可以关闭前端并在后台运行，但电脑必须保持唤醒。电脑关机、休眠、asHub 完全退出时不会执行，也不会由服务器代执行。
- 对话忙碌时等待空闲，不插队、不打断当前任务。允许延迟包含等候时间，超过期限的消息不会开始执行。
- 默认错过时间即跳过。高级选项可选择「期限内补执行最近一次」，不会补发所有错过的轮次。默认允许延迟 30 分钟，可设 1–1440 分钟。
- 同一任务上一轮尚未结束时跳过下一轮，避免重叠；相邻自动提交不足一分钟也会跳过。固定间隔最少 5 分钟。
- 暂停、删除或停用插件取消尚未开始的投递，已开始的对话继续运行。停用插件不会删除计划；重新启用后按照错过时间策略处理后续计划。
- 重启后，已经提交但执行结果不确定的轮次标记为中断，**不自动重发**。请先核查目标对话的实际结果，再决定是否手动执行。
- 目标对话被归档、删除或不可用时，任务会在到期检查时暂停。重新选择目标或恢复任务需重新确认。
- 工作日指周一至周五，不包含法定节假日规则。夏令时不存在的本地时刻跳过，重复时刻只执行第一次。任务时区不会随系统时区自动改变。
- “本轮已结束”仅代表模型本轮回复结束，不代表打卡等业务结果已成功；结果以目标对话中的核验为准。插件不自动重试失败或结果不确定的业务操作。

消息中可使用 `{{scheduled_date}}`、`{{scheduled_time}}`、`{{triggered_time}}`，分别替换为计划日期、计划日期时间和实际提交日期时间。第一版通过插件菜单配置任务，不注册让模型自行创建定时计划的工具。

## 数据与测试

任务保存在 asHub 会话目录下的 `plugin-data/<插件标识>/tasks.json`；授权和投递回执保存在同目录的 `extension-messages.json`。请勿手动清除尚在运行的回执。单插件最多 100 个任务，每任务显示最近 50 条记录并保留未结束记录；宿主授权和回执各有 20,000 条保护上限，达到后会拒绝新提交，不会静默清理去重数据。

```sh
node --test tests/*.mjs
```

仓库级验证：`npm run test:scheduled-tasks`；真实 Chromium 界面验证：`npm run test:scheduled-tasks:ui`。测试使用隔离的临时目录和模拟对话，不调用模型或真实网站。
